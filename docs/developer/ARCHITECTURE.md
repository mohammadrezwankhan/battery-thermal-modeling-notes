| Component | Data flow and responsibility | Boundary |
|---|---|---|
| `LumpedThermalSpec` | Immutable parameters; validation, resistance, reversible heat and radiation methods | One temperature state; no electrical SOC/voltage model |
| CSV loader | Strict ordered headers → finite, contiguous piecewise-constant schedules | No interpolation or measured-data provenance inference |
| `simulate_lumped_temperature` | Parameters/schedules → start rates → Euler, exact-linear or internally subdivided RK4 → interval/state arrays | No adaptive error tolerance or controller |
| `ThermalSimulation` | N+1 times/temperatures, N interval quantities; derived energy and limit metrics | Stored interval rates are sampled at interval starts |
| CLI and CSV writers | Resolve input conflicts, run model, write selected outputs, print summaries | Runs locally; a printed exceeded limit still returns 0 |
| Browser lab | Embedded JSON → pure JavaScript thermal response → chart/checkpoints/CSV download | Does not call Python or consume the native CSV fixtures |
| Native catalogue and portfolio guide | Source links, search, copied commands; portfolio personal notes/study-plan export | Learning progress does not certify command execution |

## Native sequence

`main` resolves profile-versus-constant inputs before constructing a specification. The simulator validates the specification and the length, finiteness and relevant positivity of every schedule, evaluates start-of-interval rates, advances temperature, validates the endpoint, and appends state-derived interval heat. The limit assessors run afterward and do not alter integration. Output files are written only when requested. [models/lumped_cell_thermal.py:750–861](https://github.com/mohammadrezwankhan/battery-thermal-modeling-notes/blob/37cb3c16069b21c373efc17ed202352ab69224dd/models/lumped_cell_thermal.py#L750-L861); [models/lumped_cell_thermal.py:874–993](https://github.com/mohammadrezwankhan/battery-thermal-modeling-notes/blob/37cb3c16069b21c373efc17ed202352ab69224dd/models/lumped_cell_thermal.py#L874-L993); [models/lumped_cell_thermal.py:1172–1327](https://github.com/mohammadrezwankhan/battery-thermal-modeling-notes/blob/37cb3c16069b21c373efc17ed202352ab69224dd/models/lumped_cell_thermal.py#L1172-L1327).

There is no server, database, package installer, native plugin system, MATLAB/Simulink implementation or notebook in the reviewed tree. `results/` is ignored; the committed CSVs are inputs. Browser bundles include nine inactive teaching model kinds as well as `thermal`; their presence does not establish implemented native capabilities or cross-repository integration.
